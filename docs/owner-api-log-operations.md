# 自有接口日志使用说明

适用人员：负责接口联调、日常使用和问题排查的甲方管理人员。

自有接口日志用于查看外部系统调用本系统接口时，发送了哪些参数、系统返回了什么内容。管理端中的功能名称为“入站接口日志”。

## 1. 从哪里进入

登录管理端后，按操作目的选择入口：

| 要做的事 | 菜单入口 |
| --- | --- |
| 开启或关闭记录、设置接口范围、调整保留天数 | 配置中心 → 入站接口日志 |
| 查询记录、查看请求参数和响应内容 | 日志中心 → 入站接口日志 |

如果看不到菜单或提示权限不足，请联系系统管理员开通相应权限。日志只能在账号有权查看的项目范围内查询。

## 2. 开始记录指定接口

以记录定位器列表和详情接口为例：

1. 打开“配置中心 → 入站接口日志”。
2. 将“是否启用接口日志”设为“开启”。
3. 将“白名单规则来源”设为“使用本页白名单”。
4. 点击“添加规则”，分别填写下面两条路径，并勾选每行的“启用规则”。
5. 点击“保存配置”，确认出现保存成功提示。

| 接口完整路径 / 通配符 | 记录范围 |
| --- | --- |
| `api/tp/locator` | 定位器列表所在的接口路径 |
| `api/tp/locator/*` | 定位器详情、删除等带有编号的接口路径，例如 `api/tp/locator/123` |

保存成功后无需重启系统。请再调用一次目标接口，稍等后到“日志中心 → 入站接口日志”查看。**只记录启用后发生的新调用，不会补录之前的调用。**

### 路径怎么填写

每行填写一条规则，最多支持 100 条。路径区分大小写，不填写域名、查询条件或请求方法。

例如，实际请求地址为：

```text
https://系统域名/api/tp/locator?third_slug=示例编号&with_area=1
```

规则应填写：

```text
api/tp/locator
```

填写时注意：

- `api/tp/locator` 与 `api/tp/locator/*` 是两条规则。只配置后者，不会记录列表路径本身。
- `*` 可以匹配路径中变化的部分，例如不同的定位器编号。
- 规则只按路径判断，不区分查询、创建、修改、删除等请求方法。同一路径上的不同操作都会记录。
- 查询条件不参与路径匹配，例如 `with_area=1` 或不同的 `third_slug` 不需要分别配置规则。
- 请按实际使用的接口路径填写；如果接口前缀不是 `api/tp`，应使用对应的实际前缀。

建议只添加需要排查的接口，避免使用单独的 `*` 大范围记录。

### 总开关、逐条开关与“继承”的区别

| 设置 | 保存后的效果 |
| --- | --- |
| 总开关选择“关闭” | 停止记录所有接口的新调用 |
| 取消某条“启用规则”的勾选 | 停用该条规则并保留路径；若请求仍命中其他已启用规则，仍会记录 |
| 删除某条规则 | 移除该条规则，不删除已经产生的日志 |
| 选择“使用本页白名单”，但规则为空或全部停用 | 不记录任何接口 |
| 选择“继承部署配置” | 使用实施人员预设的设置，不以当前页面中填写的覆盖值为准 |

总开关开启，并不代表所有接口都会记录。使用本页白名单时，请同时确认目标路径命中了已启用的规则。

总开关与统一配置中心共用同一项设置，在本页操作即可，无需重复配置。需要自己维护记录范围时，使用“使用本页白名单”；不确定“继承”后的范围时，请先与实施人员确认。

### 哪些接口不能在这里开启记录

配置页下方会显示“高频接口固定排除”清单。这些接口包括部分实时定位、历史轨迹等高频查询，为控制系统负担，始终不记录。即使添加了对应白名单，也不会生效。如确需排查此类接口，请联系实施人员。

## 3. 查询日志和查看详情

打开“日志中心 → 入站接口日志”，填写筛选条件后点击“查询”；点击“重置”可清空筛选条件。

| 筛选条件 | 使用方法 |
| --- | --- |
| 请求 ID（精确） | 已取得请求 ID 时优先使用，可查找同一次调用的记录 |
| 项目 UUID（精确） | 填写项目的完整 UUID；不清楚时可向项目管理员确认 |
| URL / 路径包含 | 填写路径或地址中的部分文字，例如 `api/tp/locator` |
| HTTP 方法 | 根据需要选择 GET、POST、DELETE 等 |
| 记录类型 | 选择“请求”或“响应” |
| 响应状态码 | 例如填写 `200` 或 `500`，只筛出响应记录 |
| 记录时间起 / 止 | 按 `2026-11-17 09:00:00` 格式填写，也可只填写起始或结束时间 |

列表按记录时间倒序显示，每页 20 条；有更多记录时，使用“上一页”“下一页”。排查特定问题时，建议先缩小时间范围或使用请求 ID。

正常的一次调用通常有“请求”和“响应”两条记录，它们的请求 ID 相同。点击任一条的“详情”，可以一起查看同一请求 ID、同一项目的关联记录：

- **请求参数**：调用方发送的查询条件或业务内容。
- **响应内容**：系统返回的数据，可用于核对是否返回空列表、错误提示等。
- **请求头及其他信息**：请求 ID、项目 UUID、请求方法、响应状态码、来源 IP、接口地址等。

JSON 内容会自动缩进，便于阅读。若出现 `[truncated]`，表示内容过长，仅保留了部分文本。详情最多展示 20 条关联记录，可通过“查看此请求的全部记录”继续查询。

**HTTP 状态码为 200，只表示本次请求正常返回。是否查到所需标签或其他业务数据，还要查看“响应内容”中的实际结果。**

## 4. 设置日志保留时间

在“配置中心 → 入站接口日志”中：

1. 将“保留时间来源”设为“使用本页保留天数”。
2. 在“日志保留天数”填写需要的整数天数，例如 `7`。
3. 点击“保存配置”。

通常默认保留 7 天；选择“继承部署配置”时，以页面提示的默认天数为准。

系统每天检查并清理超过保留时间的历史日志，不会在修改天数后立即清理。缩短保留时间后，超期记录会在后续清理时删除，删除后无法在本页面找回。需要保留用于排障的内容，请在清理前联系负责人员处理。

关闭日志采集只停止产生新记录，已有日志仍按保留时间自动清理。

## 5. 常见问题

| 现象 | 建议检查或处理方式 |
| --- | --- |
| 开关已经开启，仍没有记录 | 确认选择了“使用本页白名单”、目标路径正确、对应规则已勾选，并已点击“保存配置”；保存后重新调用接口，稍等再查询 |
| 详情接口有记录，列表接口没有 | 检查是否只填写了 `api/tp/locator/*`；列表路径还需单独添加 `api/tp/locator` |
| 只有部分接口有记录 | 检查规则是否匹配，以及目标接口是否在“高频接口固定排除”清单中 |
| 按状态码查询后只看到“响应” | 这是正常情况；点击“详情”可查看关联请求 |
| 只有请求，暂时没有响应 | 稍等并刷新；仍缺少时，记录请求 ID、接口地址和发生时间，交给技术人员排查 |
| 页面提示未启用数据库日志后端 | 本页面只显示保存到本地数据库的日志。如果部署使用云日志，新记录需由技术人员在云日志中查询；联系实施人员确认查看方式 |
| 已有历史记录，但新调用没有出现 | 历史记录仍可查看，不代表当前仍在记录；检查当前开关、规则及页面上的日志后端提示 |
| 记录早于当前保留天数却仍存在 | 清理每天执行，并非实时删除；超过下一次清理周期仍未清理时，联系实施人员检查 |

无法自行定位时，请向技术人员提供：发生时间、接口地址、请求 ID（如有）、筛选条件，以及相关页面截图。
